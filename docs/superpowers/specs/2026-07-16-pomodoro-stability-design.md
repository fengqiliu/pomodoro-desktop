# Pomodoro 稳定性加固设计

日期：2026-07-16  
状态：待用户书面审阅

## 1. 背景

当前应用已经具备三阶段计时、任务、七天统计、噪音、主题、国际化、全局快捷键、系统托盘、关闭到托盘和原生通知。整体技术路线保持轻量：React 负责界面和计时流程，Tauri 提供桌面能力，数据保存在本地。

随着通知、自动衔接和托盘能力加入，现有实现出现了几类稳定性风险：长休息周期判断不正确、跨午夜统计可能串日、运行中修改设置会影响当前会话的显示与记账、设置弹窗超过固定窗口高度、快捷键和通知错误缺少用户反馈。本设计先解决这些基础问题，不扩展产品范围。

## 2. 目标

本阶段完成后，应用应满足：

- 专注、短休息和长休息按照确定规则转换。
- 暂停、恢复、后台节流和运行中修改设置不会造成倒计时漂移或统计错误。
- 应用长期驻留托盘跨过午夜时，今日统计仍按本地日期正确归属。
- 所有设置在 380×580 固定窗口内可访问，并支持基本键盘操作。
- 快捷键和通知失败对用户可见，已有有效配置不会被无效输入破坏。
- 浏览器开发模式与 Tauri 桌面模式继续共用同一套前端。
- 现有任务、设置和历史数据保持兼容。

## 3. 非目标

本阶段不实现：

- 账号、云同步或后端服务。
- SQLite、Redux 或其他全局状态库。
- 将计时器整体迁移到 Rust。
- 任务标签、预计番茄数、归档或复杂统计。
- 应用完全退出后的自动补记专注会话。
- 大规模拆分 `App.tsx` 的界面组件。

## 4. 方案选择

采用“渐进式加固”方案：保留 React、Tauri、`localStorage` 和当前单页 UI，只提取可以独立测试的纯计时函数。该方案改动面较小，也不会破坏普通浏览器中的 UI 调试能力。

本阶段不采用原生 Rust 计时器。当前墙钟截止时间已经能消除 `setInterval` 累积漂移；原生计时器只有在后续需要更强的休眠恢复、托盘倒计时或操作系统级调度时才值得引入。

## 5. 计时领域模型

### 5.1 单次会话快照

每次进入一个阶段时确定该会话的总时长，并在会话结束前保持不变：

- `sessionDurationSeconds`：阶段开始时从设置读取的总秒数。
- `secondsLeft`：暂停状态和界面展示使用的剩余秒数。
- `endAt`：运行状态下的墙钟截止时间。
- `phase`：`focus`、`short` 或 `long`。
- `running`：当前是否运行。

点击开始或恢复时，使用 `Date.now() + secondsLeft * 1000` 设置 `endAt`。运行期间每次刷新都由 `endAt - Date.now()` 推导剩余时间。设置变化只影响后续新阶段，不改变当前会话的 `sessionDurationSeconds`、进度环分母或最终记账分钟数。

手动切换阶段、重置阶段和阶段自然结束时，重新创建会话快照。

### 5.2 长休息周期

阶段转换使用完成后的专注次数判断：

```text
nextCompleted = completedToday + 1
isLongBreak = nextCompleted % longEvery == 0
```

因此默认配置下，第 4、8、12 次专注结束后进入长休息，第 5 次专注结束后仍进入短休息。手动“跳过”专注阶段不增加完成次数，也不消耗长休息周期。

本阶段继续使用 `completedToday` 计算周期，不新增持久化字段。跨日后周期随今日统计重置，这是当前产品语义。

### 5.3 进度

进度统一计算为：

```text
progress = 1 - secondsLeft / sessionDurationSeconds
```

结果限制在 `0..1`。任何设置更新都不能让正在运行的进度环跳变、倒退或超过范围。

## 6. 跨日与历史归属

新增统一的日期滚动检查。它在以下时机执行：

- 应用加载状态时。
- 计时器每次 tick 处理前。
- 窗口重新获得焦点或文档从隐藏变为可见时。
- 修改今日统计前。

当持久化日期与当前本地日期不同：

- `completedToday` 和 `focusMinutesToday` 重置为 0。
- 持久化日期更新为当前日期。
- 任务列表、任务累计番茄数、设置和历史不重置。

跨午夜完成的专注会话整体记入完成日期，不拆分分钟。历史记录仍按当前本地日期写入。这样规则简单、可解释，并与“完成一次番茄后才记账”的现有行为一致。

## 7. 设置与输入校验

### 7.1 时长设置

保存或失去焦点时进行规范化：

- 专注时长：1–120 分钟。
- 短休息和长休息：1–60 分钟。
- 长休息间隔：2–10 次。
- 噪音音量：0–1。

空值、非数字和越界值不能进入持久化状态。无效输入恢复为最后一个有效值，而不是依赖 HTML `min`、`max` 属性。

### 7.2 快捷键

设置弹窗使用独立的 `hotkeyDraft`，输入过程中不注册快捷键。用户确认设置时才尝试注册：

1. 保留当前已生效快捷键。
2. 校验草稿非空且至少包含一个普通键。
3. 尝试注册新快捷键。
4. 成功后再注销旧快捷键并持久化新值。
5. 失败时保留旧快捷键，显示本地化错误信息。

浏览器模式显示“仅桌面端生效”，不尝试注册。

## 8. 通知行为

用户开启通知时主动请求权限，而不是等到阶段结束才请求。结果分为：

- 已授权：保持开启。
- 已拒绝或系统不支持：关闭开关并显示说明。
- 浏览器开发模式：保持无操作，但明确标注桌面端能力。

通知正文根据自动衔接状态变化：

- 自动衔接已开启：说明下一阶段已经开始。
- 自动衔接未开启：说明下一阶段已经准备好，等待用户开始。

通知失败不影响阶段转换、历史记账或提示音。

## 9. 设置弹窗与可访问性

设置弹窗必须适配固定窗口：

- 弹窗最大高度不超过视口可用高度。
- 标题和底部操作区保持可见。
- 中间内容区独立垂直滚动。
- 打开后焦点进入弹窗；关闭后焦点返回设置按钮。
- `Escape`、关闭按钮和点击遮罩均可关闭。
- 开关提供 `aria-pressed` 或等效状态语义。
- 标签页提供选中状态语义。
- 主播放/暂停按钮具有随状态变化的可访问名称。
- 任务完成控件改用原生 `button`，支持 Tab、Enter 和 Space。
- 所有交互控件具有清晰的 `:focus-visible` 样式。

本阶段只改善结构和可操作性，不重新设计颜色、字体或整体视觉风格。

## 10. 代码边界

继续保留 `App.tsx` 作为单页 UI，但新增一个小型纯逻辑模块，例如 `src/timer.ts`，包含：

- 阶段时长计算。
- 下一个阶段计算。
- 长休息周期判断。
- 进度限制。
- 设置数值规范化。

这些函数不得访问 React、DOM、`localStorage` 或 Tauri API。`platform.ts` 继续作为前端调用原生能力的唯一入口。持久化仍由现有版本化键负责，本阶段不改变存储结构，因此不提升 `pomodoro-state-v2` 的版本。

## 11. 错误处理

- `localStorage` 解析失败时继续回退到默认状态。
- 写入存储失败时不使计时器崩溃；开发环境记录错误。
- 快捷键注册失败必须显示在设置界面。
- 通知权限拒绝必须显示在设置界面。
- 音频不可用仍按现有最佳努力策略处理，不阻塞阶段完成。
- 原生能力失败不得影响浏览器模式。

## 12. 测试策略

引入 Vitest，只测试纯逻辑和关键状态规则，不在本阶段搭建大型端到端测试体系。

自动化测试至少覆盖：

- 第 4、8 次完成进入长休息，第 5 次进入短休息。
- 跳过阶段不增加完成次数。
- 运行中修改时长不改变当前会话快照。
- 暂停后恢复使用新的 `endAt`，剩余时间不丢失。
- 进度始终位于 `0..1`。
- 时长和长休息间隔被正确限制。
- 跨日只重置今日汇总，不删除任务和历史。
- 跨午夜完成的会话记入完成日期。

验证命令：

```bash
npm run typecheck
npm run test
npm run build
```

桌面端手工检查：

- 全局快捷键成功、冲突和无效输入。
- 通知授权、拒绝和阶段结束通知。
- 关闭到托盘后计时继续。
- 380×580 窗口中设置弹窗可以完整操作。

浏览器端手工检查：

- 页面可正常加载。
- 计时、任务、统计、主题和噪音仍可使用。
- 桌面专属能力无操作且不会抛错。

## 13. 实施顺序

1. 同步现有依赖，恢复类型检查和构建基线。
2. 提取纯计时函数并补充测试。
3. 引入会话时长快照，修复长休息周期和进度计算。
4. 实现跨日检查与完成日期归属。
5. 实现设置校验、快捷键草稿和错误反馈。
6. 调整通知授权与通知文案。
7. 修复设置弹窗滚动和键盘可访问性。
8. 更新中英文文案与项目说明。
9. 执行自动化检查和桌面/浏览器手工验收。

## 14. 验收标准

- 默认设置下，第 4 次专注后进入长休息，第 5 次后进入短休息。
- 运行中的计时不受设置变化影响，完成分钟与会话开始时长一致。
- 应用跨过本地午夜后，今日统计归零且历史、任务保持不变。
- 设置弹窗所有字段和按钮在 380×580 窗口中可访问。
- 无效快捷键不会替换当前有效快捷键，并显示明确反馈。
- 通知正文准确反映下一阶段是否自动开始。
- 浏览器模式没有直接导入 Tauri API。
- 现有持久化数据无需迁移且不丢失。
- 类型检查、单元测试和生产构建全部通过。

## 15. 后续演进

稳定性阶段完成后，再分别评估：

- 任务预计番茄数、编辑和归档。
- 30 天趋势、连续专注天数和数据导入导出。
- 托盘显示当前阶段和剩余时间。
- 应用完全退出后的会话恢复策略。
- 是否需要将后台计时下沉到 Rust。

这些能力不应混入本阶段，以免扩大回归范围。
