## 1. 引言

### 1.1 编写目的

描述系统的总体架构、模块划分、关键机制、数据结构、接口与错误处理策略，为开发维护与后续演进提供设计基线。

### 1.2 设计总原则

1. **分层（DDD）**：前端按 domain（纯规则）/ application（端口与用例）/ infrastructure（适配器）/ presentation（组装与展示）分层；计时机制收敛在引擎 hook；阶段结束的业务规则通过 `onPhaseComplete` 回调注入；领域与应用层不触碰 IO/React/Tauri，可直接单测。
2. **平台抽象**：原生能力统一走 `infrastructure/platform/` 适配器（惰性动态导入 Tauri API + `isDesktop()` 特性检测），浏览器端自动降级 no-op，避免运行时解析失败。
3. **纯函数领域层**：计时规则、统计、备份校验、原生计时器均为纯逻辑，不触碰 IO，可直接单测。
4. **持久化版本化**：localStorage 键带版本后缀，结构变更时递增后缀、不做迁移。

## 3. 模块设计

### 3.1 `presentation/App.tsx` —— 组装层

- **职责**：组合 `hooks/*` 状态/副作用钩子与 `components/*` 展示组件（`TasksView` 由 `TaskAddForm`/`TaskFilterBar`/`TaskItem` 组成，`StatsView` 内含 `TrendPanel`/`CategoryBreakdown`/`EstimateAccuracy` 卡片）；自身仅保留 UI 态（tab/chartMetric）与派生值（progress/accent/week）。业务规则与副作用不在本文件。
- **hooks 分工**（均由 App 组装）：
  - `usePersistedState`：全部持久化领域状态（settings/tasks/dailyProgress/cycleFocusCount/noise/history）+ 启动时历史裁剪 + localStorage 持久化 + 午夜/前台跨日守卫。
  - `usePomodoroSession`：接线计时引擎与阶段完成业务用例（调用 `application/completePhase` 编排周期推进、今日统计、历史记录、任务计数、提示音、通知意图，并分发状态更新）；注入引擎的回调：
    - `getPhaseSeconds(phase)`：阶段 → 配置秒数。
    - `getCompletionNotification()`：基于 `buildPhaseNotificationDescriptor` 生成原生通知文案；通知开关关闭或浏览器端返回 `undefined`。
    - `onPhaseComplete(finished, nativeNotificationSent)`：调用 `completePhase` 应用服务，触发副作用后返回 `{ nextPhase, nextSeconds, autoStart }` 交给引擎执行。
  - `useTaskList`（任务操作：增删/勾选/清除、行内重命名、预估更新、上下移排序 + 当前专注任务；删除与清除已完成通过 `showToast` 提供「撤销」）、`useSettingsDialog`（弹窗开关、热键草稿确认制、恢复默认）、`useHotkey`（全局热键注册与错误态）、`useAppShortcuts`（窗口内 Space/R/S/I/E 与 Ctrl/⌘+Z 撤销；聚焦在按钮、复选框、开关时 Space 交还该控件）、`useBackup`（剪贴板备份导入导出）、`useWeeklyReport`（周报汇总消费 + CSV 剪贴板导出）、`useToast`/`useTheme`/`usePinned`/`useLanguage`/`useNoise`/`useDocumentTitle`/`useMidnightRollover`（各自独立的 state + effect）、`useTrayTooltip`（运行中把「倒计时 · 阶段」写到托盘悬停提示，空闲时回落为应用名）、`useInterruptions`（专注打断记录：判定当前能否记录、返回今日走神/被打扰计数、把打断写入当日历史）。

### 3.2 `presentation/hooks/usePomodoroEngine.ts` —— 计时引擎

只拥有「倒计时机制」，不含业务规则。

- **对外接口**：`{ phase, secondsLeft, running, toggle, reset, switchTo, skip, syncIfIdle }`。
- **核心状态**：
  - `endAtRef`：墙上时间截止点，启动时计算 `now + seconds*1000`；1 秒绘制循环只做 `remaining = max(0, round((endAt-now)/1000))`。
  - `countdownActionRef`：每次开始/暂停/取消自增；异步（如原生 start）返回后校验 action 未变，否则补发取消并丢弃结果——防止旧请求覆盖新状态。
  - `nativeTimerGenerationRef / nativeTimerRunningRef / nativeTimerListenerReadyRef`：原生计时桥接状态。
  - `completionInFlightRef`：完成流程防重入；`toggleInFlightRef`：开始/暂停串行化（全局快捷键可能双触发）。

### 3.3 `domain/timer` —— 纯计时规则

- `completeFocusCycle(count, longEvery)`：完成一次专注后计算下一阶段与周期计数（达到间隔 → 长休且归零；否则 → 短休且 +1；入参防御：非法值回退 1、负值取 0）。
- `nextPhaseAfterCompletedBreak()`：休息完成 → 专注；`nextPhaseAfterSkip(phase)`：专注 → 短休，其余 → 专注（跳过不计入周期）。
- `resetDailyProgressIfNeeded(progress, today)`：日期不同则归零今日计数；`addCompletedFocus(progress, minutes)` 累加今日番茄与专注分钟。
- `isDailyGoalReached(progress, goal)`（每日目标达成判定，`goal ≤ 0` 视为关闭）、`getDailyGoalPercent(progress, goal)`（达成率百分比，封顶 100）。
- `remainingSeconds(endAt, now)`、`focusesUntilLongBreak(count, longEvery)`。

### 3.4 `infrastructure/platform/` —— 平台抽象层

- `isDesktop()`（`runtime.ts`）：`window.__TAURI_INTERNALS__` 存在即桌面端。
- 适配器（实现 `application/ports.ts` 端口）：`windowAdapter.setAlwaysOnTop/isAlwaysOnTop`、`shortcutAdapter.register/unregister`、`nativeTimerAdapter.start/pause/cancel/listenCompleted`、`trayAdapter.setTooltip(text)`（调用 `set_tray_tooltip` 命令，纯装饰、失败静默）、`notificationAdapter.notifyPhaseDone(title, body)`（首次发送时才请求通知权限）。
- 模块级缓存已加载的 Tauri API 命名空间；所有调用 try/catch，失败返回 `null/false` 或静默；浏览器端原生计时器返回 `null` 走本地回退。

### 3.6 `src-tauri/` —— Rust 原生层（限界上下文 + 组合根）

**`lib.rs`（组合根）**

- 仅装配：注册 `NativeTimer` 状态、global-shortcut / notification 插件、四个命令（`timer::commands::*` 三个计时命令 + `tray::set_tray_tooltip`）、托盘 setup、关闭到托盘拦截。
- `manage` 注入 `CompletionLogHandle`（`timer/completion_log.rs`）：setup 中以 `app.path().app_data_dir()` 创建 `FileCompletionLog`，路径解析失败回退 `NullCompletionLog`。
- 窗口生命周期：`CloseRequested` 拦截 → 隐藏到托盘（不退出），仅托盘「退出」终止进程。
- `timer/commands.rs`（IPC 适配器）：`native_timer_start` 启动计时并 spawn 完成 worker——先按传入通知配置发系统通知（`notificationSent` 记录成败），再向注入的日志记录一次完成（best-effort），最后 `emit("native-timer-completed", {snapshot, notificationSent})`。

**`timer/engine.rs`（计时引擎）**

- 数据：`Arc<Mutex<TimerState>>`（generation/running/endAtMs/remainingMs）+ 可注入 `Clock`（生产 `SystemClock`，测试用假时钟）。
- 操作：
  - `start(durationMs)`：代际 +1，`endAtMs = now + duration`，返回 `(TimerSnapshot, TimerTicket)`。
  - `pause()`：按墙上时间求剩余并保存；代际 +1 使进行中的 worker 轮询失效。
  - `cancel(expectedGeneration?)`：无参取消当前；带参仅当传入代际等于当前代际才取消——旧代际的定向取消不影响新计时器。
  - `poll(ticket)`：`Pending(remainingMs) / Completed(snapshot) / Cancelled`（代际不匹配即 Cancelled）。
- `spawn_completion_worker(ticket, on_complete)`：循环 poll，剩余 >1s 睡 1s，否则睡 `min(剩余, 1s)`，到期触发回调——托盘驻留时通知与事件依然可靠送达。

**`timer/completion_log.rs`（完成审计日志，仓储端口注入）**

- 端口 `CompletionLog`：`record(&CompletionEntry)`，约定 best-effort（写失败绝不影响计时器与命令）。`CompletionEntry { completedAtMs, durationMs, generation, notificationSent }`（camelCase JSON）。
- 实现：`FileCompletionLog`（追加写 `<app_data_dir>/completion-log.jsonl`，按需创建父目录、失败静默）；`NullCompletionLog`（无操作默认）；`CompletionLogHandle`（Tauri 管理状态包装，持有 `Arc<dyn CompletionLog>`）。
- 装配与消费：组合根注入 handle；`commands.rs` 完成回调中、事件 emit 前记录。`engine.rs` 零改动、保持纯逻辑可测。

**`tray/`（托盘上下文）**

- `build_tray`：`TrayIconBuilder`（id `main`），复用 `tauri.conf.json` 打包图标；菜单「显示/隐藏 / 退出」；左键单击切换窗口显隐（`toggle_window`）。`set_tray_tooltip(text)` 命令更新托盘图标的悬停提示（找不到托盘时静默忽略）；前端 `useTrayTooltip` 在运行中写入「倒计时 · 阶段」，空闲时恢复为应用名。

## 4. 关键机制设计

### 4.1 墙上时间倒计时

不采用 interval 累加（易受后台节流/抖动影响），而是记录截止点 `endAt`，每次 tick 用 `now` 反算剩余。React 只负责绘制（1s paint loop）与业务规则，不承担计时精度责任。

### 4.2 双计时适配器

| 场景 | 开始 | 到期判定 | 通知 |
| --- | --- | --- | --- |
| 桌面端 | `native_timer_start` 交 Rust（快照回填 generation） | Rust worker 按墙上时间判定 → emit 事件（先通知后事件） | 原生 worker（`notificationSent` 透传前端去重） |
| 浏览器端 | 跳过原生桥接（`isDesktop()` 为假，`nativeTimerAdapter.start` 返回 null） | paint 循环发现 remaining ≤ 0 本地完成 | 无（`notifyPhaseDone` no-op） |

两端口径一致：同一份结束时间戳算法（`remainingSeconds`）。

### 4.3 代际取消与并发防护

- **代际**：前端 `countdownActionRef` 与 Rust `generation` 双重防线。任何异步结果回来先校验「代际/序号仍为最新」，否则丢弃或补发取消。
- **防重入**：`completionInFlightRef` 保证完成流程串行；`toggleInFlightRef` 保证开始/暂停不因全局快捷键双触发而错乱。
- **卸载清理**：引擎卸载时取消监听、取消原生计时；快捷键注册 effect 卸载时注销。

### 4.4 每日重置（5 个触发点）

今日统计日历绑定，周期计数跨日延续。校验点：① 启动加载；② 午夜定时器（`setHours(24,0,0,50)` 后自续）；③ 窗口 `focus`；④ `visibilitychange` 变为可见；⑤ 完成专注与持久化写入前防御性校验。

### 4.5 历史自动裁剪

`pruneHistory` 构造近 60 天合法键集合，仅保留命中的记录；触发点：启动、记录、导入。图表只取近 7 天。

### 4.6 备份安全导入

导出：完整 state + history → 剪贴板（失败 Toast）。导入：剪贴板 → 不可用时 `prompt` 粘贴兜底 → `parseBackup` 校验（app 标识、state/history 为对象）→ `mergeState` 默认值合并 + 历史裁剪 → 写入并 `location.reload()`；校验失败仅 Toast，不写盘。

### 4.7 设置保存与快捷键草稿

设置面板编辑期只更新 `hotkeyDraft`（草稿），点击「完成」校验非空后才提交；提交后由 effect 统一「注销旧键 → 注册新键」，失败置 `hotkeyError=registration` 并告警。`syncIfIdle` 保证暂停状态下修改时长后倒计时对齐新值，运行中的计时不受影响。

### 4.8 每日目标、连击与噪音随专注

- **每日目标**：`completePhase` 计算 `goalReachedJustNow = goal > 0 && 完成后达标 && 完成前未达标`，仅在由未达成→达成的瞬间置位，`usePomodoroSession` 据此触发一次性 🎉 Toast 庆祝；计时页用 `getDailyGoalPercent` 展示达成率，`isDailyGoalReached` 生效后显示 ✓ 徽标。
- **连击与累计**：`calculateStreak` 以「含 ≥1 番茄的自然日」判定连续；今日无记录则从昨日延续（当日宽限），昨日也无才归零；`calculateTotalStats` 全量累加历史。二者均为纯函数，由 `StatsView` 消费。
- **噪音随专注**：`useNoise` 播放条件 = `autoWithFocus ? (noise.on && running && phase === "focus") : noise.on`，实现「专注时自动伴音、暂停/休息自动暂停」，且关闭该选项后行为与旧版完全一致。

### 4.9 周报导出与完成审计日志

- **周报/CSV 导出**：规则全部在 `domain/stats/weeklyReport.ts`（`summarizeWeek` 周汇总 / `buildWeeklyReportCsv` 明细 + 汇总行，标签注入、字段转义；明细含走神/被打扰两列，`best-day` 行的两列留空），视图仅在 `StatsView`（本周简报：活跃天数、打断次数及分类、最佳日 + 导出按钮），`useWeeklyReport` 负责把 CSV 写入剪贴板并 Toast（成功 `toast.exported` / 失败 `toast.copyFailed`），与备份导出一致。
- **完成审计日志**：桌面端每次计时到点完成，worker 依次执行「发系统通知 → 记录 `CompletionEntry`（追加 `<app_data_dir>/completion-log.jsonl`）→ emit 完成事件」；日志为 JSON Lines 审计文件，best-effort、失败静默，不参与业务状态；`engine.rs` 保持纯净（端口注入，组合根装配）。

### 4.10 专注打断记录

- **可记录条件**：`canLogInterruption(phase, running, secondsLeft, phaseSeconds)` —— 仅专注阶段，且已开始（运行中，或暂停在中途；被打断时的常见反应就是先暂停）。专注未开始与休息阶段不显示入口。
- **入口**：计时环中央「💭 走神 N」「👤 被打扰 M」两个按钮（N/M 为今日计数），或快捷键 `I`（走神）/ `E`（被打扰）；`useInterruptions` 负责判定与写入，`useAppShortcuts` 只分发。
- **存储口径**：`interruptions` 恒为当日总数，`externalInterruptions` 为其中被他人/外部打断的次数，走神 = 总数 − 被打扰；不引入新键，旧记录缺字段按 0 读取，未分类的旧打断计入走神。

### 4.11 预估准确度

`calculateEstimateAccuracy(tasks)` 对比任务预估与实际番茄数，只统计「已完成 + 有预估 + 实际 ≥ 1」的任务：进行中的任务计数仍在增长，无预估无从比较，而实际为 0 的已完成任务只是被直接勾选、从未计时——0 代表「没有数据」而非「几乎不花时间」，计入会把统计误判成严重高估。偏差 = `(实际 − 预估) / 预估` 四舍五入，±15% 内视为准确。卡片位于统计页折叠区，在分类分布之下。

### 4.12 任务筛选、搜索与排序

筛选状态（状态 / 分类 / 关键字）由 `TasksView` 持有，`filterTaskEntries` 返回带「原始下标」的可见项；上移/下移按相邻**可见**任务的原始下标调用 `reorderTask`，因此在筛选视图下重排会跳过被隐藏的任务，切回全部视图后顺序仍然正确。编辑行失焦（含点击筛选/搜索控件）即保存，`Enter` 保存 / `Esc` 取消；编辑草稿放在 `TaskItem` 内并以任务当前值初始化，保证行在编辑态重新挂载时不会显示空值。

### 4.13 删除撤销与带操作的提示条

`useToast` 的提示可附带一个操作按钮（`{ labelKey, titleKey?, onAction }`），带按钮时停留 5 s（普通提示 2.6 s），点击后执行操作并关闭。`runToastAction` 统一执行当前提示的操作，按钮点击与 `Ctrl/⌘+Z`（`resolveShortcut` 返回 `undo`，输入框内不拦截）都走它；没有可执行操作时为空操作，所以重复按键不会重复恢复。删除任务与「清除已完成」立即生效，并在提示条上提供「撤销」：撤销记录由 `splitTasks` 在删除时生成，恢复由 `restoreRemovedTasks` 完成；被删任务若是当前专注任务，撤销时一并恢复（仅在此时尚未选择其他任务的情况下）。提示过期后撤销记录随闭包释放，不做持久化——撤销只覆盖「刚刚误删」的场景。

## 5. 数据设计

### 5.1 localStorage 键表

| 键 | 内容 | 结构变更策略 |
| --- | --- | --- |
| `pomodoro-state-v3` | settings/tasks/completedToday/focusMinutesToday/date/cycleFocusCount/noise | 递增后缀，不迁移 |
| `pomodoro-history-v1` | `Record<dateKey, DayRecord>`（`DayRecord` 新增的字段均为可选，旧记录缺字段按 0 读取，因此无需升级键后缀） | 同上 |
| `pomodoro-theme` / `pomodoro-pinned` / `pomodoro-lang` | light\|dark / "1"\|"0" / zh\|en | — |

### 5.2 核心类型

- `Settings { focus, short, long, longEvery, dailyGoal, sound, notifications, autoStartBreaks, autoStartFocus, hotkey, noiseType, noiseVolume }`（`dailyGoal` 默认 8，0 = 关闭）
- `Task { id: uuid, title, done, pomodoros, estimatedPomodoros?, category?, completedAt? }`；`NoisePref { on, type, volume, autoWithFocus? }`
- `PersistedState`（5.1 全量结构）；`DayRecord { date, dayIndex, pomodoros, minutes, interruptions?, externalInterruptions? }`；`WeekSummary { totalPomodoros, totalMinutes, activeDays, avgPomodoros, avgMinutes, bestDay, bestPomodoros, totalInterruptions, externalInterruptions, avgInterruptions, avgExternalInterruptions }`（周报派生，不持久化）；`EstimateAccuracy { sampleCount, estimated, actual, over, under, exact, biasPercent, bias }`（统计页派生，不持久化）
- Rust：`TimerSnapshot { running, remainingMs, generation }`（camelCase 序列化，与 TS 契约对齐）；完成事件在其上扁平追加 `notificationSent`；审计日志条目 `CompletionEntry { completedAtMs, durationMs, generation, notificationSent }`。

## 6. 接口设计

### 6.1 Tauri 命令（前端 → Rust）

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `native_timer_start` | `durationMs: u64`、`notification?: {title, body}` | `TimerSnapshot` |
| `native_timer_pause` | — | `TimerSnapshot`（暂停后剩余） |

| `set_tray_tooltip` | `text: String` | —（纯装饰，失败静默） |

### 6.2 事件（Rust → 前端）

`native-timer-completed`：`TimerSnapshot & { notificationSent: boolean }`；前端按 `generation` 过滤过期事件。

### 6.3 原生权限（`capabilities/default.json`）

`core:default`、窗口置顶读写（allow-set/is-always-on-top）、global-shortcut register/unregister/is-registered、`notification:default`。

### 6.4 内部约定

- 组件一律 Props 驱动 + `tr(key, params?)` 文案函数；禁止直接访问 Tauri API。
- 持久化结构修改 → 递增键后缀。

## 7. 界面设计

- **组件树**：`App → TopBar + Tabs + (TimerView | TasksView | StatsView) + SettingsModal? + Toast?`；`TasksView → TaskAddForm + TaskFilterBar + TaskItem[]`；`StatsView → 汇总卡 + 7 天图 + 折叠区（TrendChart + MonthSummaryCard + CategoryBreakdownCard + EstimateAccuracyCard）+ 本周简报`。样式按归属拆分：`App.css` 仅留主题变量、全局元素与跨组件共享类，各组件同目录自带 CSS，`a11y.css` 在 `main.tsx` 中最后导入。
- **窗口**：380×580、居中、不可缩放/最大化、可最小化；标题在运行中镜像倒计时。
- **主题机制**：CSS 变量 `:root` / `[data-theme="dark"]`；阶段强调色经 `App` 行内 `--accent` 覆盖（红/绿/蓝）。
- **无障碍**：可点击元素均为真实 `<button>` 或带正确 ARIA 角色且可聚焦（完成框 `checkbox`、任务标题 `button`、设置开关 `switch`）；切换类按钮带 `aria-pressed`（搜索开关为 `aria-expanded`）；`:focus-visible` 焦点环由 `a11y.css` 统一恢复；尊重 `prefers-reduced-motion`；所有 `aria-label`/`title` 走 i18n。
- **设置面板交互**：模态对话框（`role="dialog"` + `aria-modal`），打开时焦点移入、Tab 在面板内循环、关闭后焦点回到触发按钮；Esc/遮罩点击关闭；快捷键编辑走草稿 + 错误提示；「恢复默认」保留噪音开关。

## 8. 错误处理与降级策略

| 场景 | 策略 |
| --- | --- |
| Tauri API 调用失败 / 浏览器环境 | 静默降级为 no-op（`null`/`false`/空函数），不阻塞功能 |
| localStorage 不可用或数据损坏 | best-effort；加载失败回退默认值 |
| 备份导入数据非法 | Toast「导入失败」，不写入任何存储 |
| 全局快捷键注册失败 | `hotkeyError=registration` 提示换组合键，应用功能不受限 |
| 通知权限被拒 | 跳过发送；桌面端 worker 的 `notificationSent` 让前端不重复尝试 |
| 音频不可用 / AudioContext 受限 | chime/noise 全程 try/catch，静默失败 |
| 持久化结构升级 | 递增键后缀；旧键自然废弃 |
